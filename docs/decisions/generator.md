# Decision: generator

Date: 2026-09-25

## Criteria
1. Templates can reference Umber Calm roles (syntax/ui/diag/term contracts), not a foreign color vocabulary.
2. Emits the hard formats: float channels (iTerm2), decimal RGB (KDE), #RRGGBBAA (VS Code).
3. Contributors can render without installing a toolchain.
4. Low lock-in; the maintainer can fix it alone.

## Results
| Option | 1 | 2 | 3 | 4 | Evidence |
|---|---|---|---|---|---|
| Custom Python (stdlib) | Yes | Yes | Yes | Yes | `prototype/proto.py` output: `Umber Calm.itermcolors` (`plutil -lint` → `OK`; float channels via `r/255`), `UmberCalm.colors` (decimal RGB `32,31,29`), `umber-calm-color-theme.json` (`#RRGGBBAA` via `P["yellow"] + "2E"` → `#DCC07D2E`). Runs with `python3 prototype/proto.py`, no dependencies beyond the stdlib. |
| Whiskers 2.9.0 (`catppuccin/tap/whiskers`) | No | Partial | Partial | No | Installed with `brew install catppuccin/tap/whiskers` (Homebrew bottle available, no Rust needed that way; the brief's `cargo install catppuccin-whiskers` fallback does need a Rust toolchain). `whiskers --list-accents` / `--list-flavors` show a fixed, hardcoded Catppuccin vocabulary: 4 flavors (latte/frappe/macchiato/mocha) × 26 named slots (rosewater…lavender, text…crust). Source (`whiskers` repo, `src/models.rs:174-223`) builds the Tera context by iterating `catppuccin::PALETTE` and inserting each `color.name.identifier()`; `--color-overrides` only replaces the hex *value* behind an existing identifier (`co.all.get(color.name.identifier())`) — it cannot add or rename a key. A template must write `{{ flavors.mocha.colors.mauve.hex }}`, never `{{ ui.focus.hex }}`. Verified live: `whiskers -f mocha --color-overrides '{"all":{"base":"201F1D"}}' iterm-test.tera` rendered `Red Component (float): 0.12549019607843137` via a hand-written `flavors.mocha.colors.base.rgb.r / 255` expression (no native float-channel filter) and `#RRGGBBAA` via the `mod(opacity=0.18)` filter → `201f1d2e`. So format needs (criterion 2) are technically reachable, but role vocabulary (criterion 1) is not — Whiskers is Catppuccin's own port-generation tool, not a generic theme generator, so lock-in (criterion 4) is high: the maintainer would have to keep remapping Umber Calm's colors onto Catppuccin's fixed identifiers forever, and fight an upstream Rust project not designed for a foreign palette. |
| Tinted Builder (`tinted-builder-rust` 0.21.0) | Partial | Partial | No | Partial | `cargo install tinted-builder-rust` — no Homebrew formula exists (`brew search tinted-builder` → "No formulae or casks found"), so every contributor needs a Rust toolchain; the install compiled ~40 crates (~43s, release profile). Per `builder.md`, template variables are generated per palette-token key, so a scheme *can* add custom keys (e.g. `syntax-keyword`, `ui-focus`) alongside the required `base00`…`base0F` slots — verified live: a `system: base16` scheme with extra `syntax-keyword`/`ui-focus` palette entries rendered `{{ syntax-keyword-hex }}` → `dcc07d` and `{{ ui-focus-dec-r }}` → `0.92941176` through `tinted-builder-rust build`. But a custom `system:` value (e.g. `umber-calm`) is rejected — a scheme without the required base16 slots errors with "base16 scheme does not contain the required palette properties", and a template config naming an unrecognized system errors with `E305: Template config missing or invalid`. So Umber Calm would still have to declare and fill 16 unused base16 slots as dead weight to pass validation. `-dec-r/g/b` and `-rgb-r/g/b` cover float and decimal RGB natively (better than Whiskers here), but Mustache is logic-less — no filters, no expressions, no arithmetic — so `#RRGGBBAA` alpha values are not derivable in-template; each alpha variant needed would have to be precomputed and stored as its own palette entry before the build, effectively requiring a Python preprocessing step anyway. |

## Decision
Custom Python (stdlib) because it is the only option that scores yes on every criterion with no compromise: templates read `syntax.keyword` / `ui.focus` / `diag.*` / `term.*` directly (already proven end-to-end in `prototype/proto.py`), f-strings can produce any of the three hardest formats — including in-template alpha blending — with evidence (`plutil -lint` OK, decimal RGB, `#RRGGBBAA`), contributors need only `python3` (already a hard project dependency per the plan's Global Constraints: "Python ≥ 3.11 standard library only"), and there is no upstream Rust/Tera/Mustache tool to depend on, patch around, or fall out of sync with — the maintainer can read and fix every line alone.

Whiskers is excluded on criterion 1: it is Catppuccin's own port-generation tool, hardcoded to Catppuccin's 4-flavor/26-color vocabulary; overrides change values, never role names, so Umber Calm's `syntax.*`/`ui.*`/`diag.*`/`term.*` contracts could never be expressed directly in a template.

Tinted Builder is closer — custom palette tokens genuinely work, verified live — but fails criterion 3 outright (no Homebrew formula, `cargo install` compiles ~40 crates) and criterion 2 is incomplete for alpha, because Mustache has no computation and pushes alpha math back into a Python preprocessing step anyway. At that point Tinted Builder adds a Rust dependency and buys nothing Python doesn't already do, more simply, with the tools the project already requires.

Not a stop condition: no existing tool clearly wins, so the plan continues (Task 5 onward) using stdlib Python as the generator.
